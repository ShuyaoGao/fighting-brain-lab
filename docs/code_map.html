格斗大脑实验台 · 代码结构图

格斗 RL 代码地图

这个仓库做三件事：用 自写的 2D 格斗游戏当训练场，用 PPO + 自博弈联赛训练神经网络，再把训练好的真实权重搬进 浏览器实验台，一边对打一边看网络在想什么。实验台另外打包成双击就能玩的免安装版 play/。下面先看全局模块图，再看训练时一个动作怎样穿过六层包装器，然后看 Python 和浏览器两份实现靠哪些测试保持一致，最后是仓库里其余的文档和文件。

~6,300行 Python（不含测试）
~3,000行浏览器 JS（arena）
12个测试文件 · 75 项测试
214维网络输入 · 31 个动作

全局模块图

从上到下是八层：入口脚本 → 智能体与联赛 → 人类条件包装器 → 自带格斗环境 → 真实游戏适配器 → 评估与基础设施 → 实验台的构建与发布 → 浏览器实验台。点任意一个文件，图上会画出它依赖谁、谁依赖它，右侧给出它的职责。

选中的文件依赖它 它依赖选中的文件 读取配置 / 生成数据 / 逐帧对拍（不是 import）

训练时，一个动作怎样走到游戏里

envs/registry.py 的 wrap_env 给游戏包了六层。网络的动作向下穿过每一层被改写成逐帧按键；游戏的状态向上穿过每一层被延迟、拼接，最后变成网络看到的 214 个数。

一套规则，两份实现

浏览器实验台不调用 Python。游戏规则和神经网络在 JS 里各重写了一遍，靠四个测试锁住和 Python 版完全一致。红色虚线就是这些“对拍”契约。

一次实验从清单到网页

规模实验（51 个模型）就是这样跑出来的。每个环节都把产物落盘，后一个环节只读前一个环节的文件。

测试在守什么

75 项测试分成三类：规则对不对、两份实现一不一样、展示有没有说谎。没有 quickjs、Chrome/Edge 或导出的模型时，相关测试自动跳过。

第一次读代码，按这个顺序

每一步只读一两个文件，读完就能看懂下一步。

  1. envs/fighting2d/constants.py 和 moves.py：按键怎么编码成 0–26，每个招式的发生、持续、收招帧。
  2. envs/fighting2d/core.py 的 step 和 observe：一帧里发生了什么，网络看到的 90 个数从哪来。
  3. envs/registry.py 的 wrap_env，再看 wrappers/human.py：人类条件是怎么加上去的。
  4. agents/ppo.py 和 scripts/train.py 里的 League：网络结构、PPO 更新、对手怎么抽。
  5. agents/policy_opponent.py：为什么评估时的网络和训练时一模一样。
  6. arena/export.py → brain.js → brainview.js：权重怎么进浏览器、大脑面板怎么画。
  7. input.js 和 coach.js：人类玩家的输入、新手模式的一键搓招，以及操作说明、招式表和练习模式。

四条最常用的命令

# 自博弈联赛训练，带 200ms 反应延迟和手速上限
python scripts/train.py --mode league --delay-ms 200 --apm 600 --out runs/my/seed0

# 按清单跑完整的规模实验（本机 3 个并行）
python -m experiments.scaling.plan run --parallel 3

# 打开格斗大脑实验台（导出本地训练的模型）
python -m arena

# 重新生成免安装版 play/ 和 release/*.zip
python -m arena.build --release

训练默认用 CPU：网络很小，CPU 比 GPU 快，也不占显存。只想玩的话不用跑任何命令，双击 play/index.html。
